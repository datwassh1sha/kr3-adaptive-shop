# Учебный frontend-проект

## Описание

Проект выполняется в рамках дисциплины «Фронтенд и бэкенд разработка».

Тема проекта: многостраничный сайт интернет-магазина или каталога услуг.

## Структура проекта

- `index.html` — главная страница;
- `catalog.html` — каталог товаров;
- `contacts.html` — контактная информация;
- `css/style.css` — файл стилей;
- `js/main.js` — файл JavaScript;
- `images/` — папка для изображений;
- `README.md` — описание проекта;
- `.gitignore` — список файлов, исключённых из Git.

- Устранено горизонтальное переполнение на ширинах 320–576 px
  (доходило до 70 px на странице товара)
- Исправлена логика стрелок ленты мероприятий: крайние положения
  определялись неверно, потому что у ленты есть внутренние отступы

Проверка результата: страницы открыты в Chromium на девяти ширинах
(320, 360, 414, 576, 768, 992, 1024, 1200, 1440 px) — горизонтальное
переполнение отсутствует на всех; вид на широких экранах не изменился.

### Changelog №7 (часть 2: респонсивные изображения)
- Для всех изображений подготовлены уменьшенные варианты: товары в
  `images/products/`, афиши мероприятий в `images/events/`
- Каждое изображение подключено через `srcset` с набором ширин и атрибут
  `sizes`, описывающий реальную долю экрана
- Фактические размеры отображения предварительно измерены в браузере на
  восьми ширинах — на их основе подобраны значения `sizes`
- На изображения добавлены `width` и `height` (защита от скачка вёрстки),
  а также `loading="lazy"`; для баннера — `fetchpriority="high"`
- В корзину записывается уменьшенная миниатюра, а не крупный файл
- В CSS добавлено `height: auto` для изображений с атрибутами размеров:
  без него браузер брал `height` как фактическую высоту и растягивал
  картинки (афиши растягивались до 1280 px)

Экономия веса изображений (замер загрузки в браузере):

| Страница | Телефон | Десктоп | Retina |
|---|---|---|---|
| Каталог | 54 KB вместо 647 KB (−**92 %**) | −92 % | −75 % |
| Главная | 215–408 KB вместо 1859 KB (−**78–88 %**) | −78 % | −38 % |
| Товар | 19 KB вместо 300 KB (−**94 %**) | −79 % | −54 % |

Проверено: пропорции блоков соответствуют CSS (карточки 6:7, афиши 3:4),
изображения не искажены, битых картинок нет, функциональность страниц
и корзины сохранена.

Ограничение: исходники баннера (739 px) и фотографий товаров (1000 px)
не покрывают экраны retina на широких экранах. Апскейл не выполнялся,
чтобы не увеличивать вес без реального прироста чёткости.

### Changelog №8 (пропорции фотографий в карточках товаров)
- Фотографии моделей вертикальные (пропорция 0.80–0.88), а блок карточки
  был горизонтальным 4:3 — при `object-fit: cover` обрезалось **около 37 %
  кадра**, то есть части модели не было видно
- Пропорция блока приведена к пропорции фотографий: **6:7**
  (у карточек каталога и блока «Популярные модели»)
- Атрибуты `width` и `height` у изображений исправлены с 400×300 на реальные
  размеры файлов (800×912, 800×944, 800×996) — иначе браузер резервировал
  место под неверную пропорцию и вёрстка «прыгала» при загрузке
- В `responsive.css` убраны ставшие ненужными правила `contain` и `padding`,
  из-за которых по краям фотографий оставались полосы

Результат: доля теряемого кадра снизилась с ~37 % до **2–3 %** — модель
видна целиком, полос по краям нет. Карточки при этом стали выше на 84–132 px,
это плата за отказ от обрезки.
